# PathSnap: Cross-Track Interface Agreements & Data Contracts

This document formalizes the contracts and data schemas agreed upon by all four team members to allow parallel development without integration bottlenecks.

---

## 1. Interface 1: Person 1 → Persons 2 & 3 (Data & Candidates)

### Candidate & Feature Table Schema
Generated by Person 1 (`features/candidate_generator.py` and `features/feature_engineering.py`), stored in `data/processed/candidates_features.parquet` (or `.csv`):

| Column Name | Data Type | Description |
| :--- | :--- | :--- |
| `trip_id` | `str` | 8-character string identifier of the trip (e.g. `'00000000'`) |
| `obs_idx` | `int` | 0-based chronological index of the GPS observation in the `.track` file |
| `gps_lon` | `float` | Raw GPS longitude (WGS84 degrees) |
| `gps_lat` | `float` | Raw GPS latitude (WGS84 degrees) |
| `gps_time` | `float` | Timestamp or elapsed seconds from `.track` |
| `arc_id` | `int` | Candidate road segment ID (0-based row index in `.arcs` file) |
| `from_node` | `int` | Starting node index of the candidate arc in `.nodes` |
| `to_node` | `int` | Ending node index of the candidate arc in `.nodes` |
| `feat_dist_to_arc` | `float` | Perpendicular/geodesic distance in meters from GPS point to arc |
| `feat_heading_diff`| `float` | Absolute heading difference (radians or degrees) between trajectory and arc direction |
| `feat_speed` | `float` | Estimated speed between consecutive GPS points (m/s) |
| `feat_time_gap` | `float` | Time gap to previous GPS point (seconds) |
| `feat_arc_length` | `float` | Length of candidate arc (meters) |
| `feat_prev_dist` | `float` | Distance from previous GPS point to candidate arc |
| `label` | `int` | Ground-truth binary label: `1` if `arc_id` matches `.route` at this step, `0` otherwise |
| `fold` | `int` | Trip-grouped CV fold assignment (`0` to `4` for 5-fold CV) |

### Road-Network Graph
- Stored as a NetworkX directed graph or adjacency structure mapping `arc_id -> (from_node, to_node, length, geometry)`.
- Node coordinates in projected coordinate space (meters) to prevent degree-based distortion.

## 2. Interface 2: Person 2 → Person 3 (Model Predictions)

### Candidate Probabilities Hand-off
Person 2 outputs calibrated probability predictions for each candidate:
- **Format**: 1D NumPy array `probabilities` of length $N$ (number of candidate rows for the trip), or a DataFrame with columns `['trip_id', 'obs_idx', 'arc_id', 'prob']`.
- **Constraint**: Strict alignment with candidate table row order. For a given `obs_idx`, the candidate $k$ with index $i$ in the candidate table must correspond exactly to index $i$ in `probabilities`.
