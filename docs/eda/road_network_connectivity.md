# Road-network connectivity EDA (Person 3 lead focus)

Analyzed 90 trips (80 train + 10 student_test), one road-network graph per trip, built from that trip's `.nodes`/`.arcs` files with `hmm/road_graph.build_road_graph`.

## Headline findings

- **1/90** trips have a single weakly-connected road network (every node reachable from every other, ignoring direction).
- **89/90** trips have more than one weakly-connected component, i.e. the road graph is fragmented.
- **0/90** trips contain at least one isolated node (degree 0 — appears in `.nodes` but is the endpoint of no arc).
- **0/90** reference routes touch more than one weak component — any such case means the ground-truth route itself crosses a disconnection, which the HMM gap-handling / shortest-path-bridge logic must account for.

Strongly-connected components (direction-aware) are typically far more fragmented than weak components, since arcs are one-way: this matters for the Viterbi transition model, where a transition between consecutive candidate arcs implicitly requires a directed path.

## Implications for the HMM decoder

- Transition probabilities use directed shortest-path distance (`hmm/road_graph.shortest_path_length_between_arcs`), which returns `inf` when the end node of one candidate and the start node of the next lie in different strongly-connected regions — these transitions must be penalised rather than treated as a normal distance.
- Large GPS gaps and genuinely disconnected consecutive observations are handled the same way in `hmm/decoder.py`: break-and-restart the Viterbi sequence, or bridge with a bounded shortest-path penalty, per trip `gap_threshold_s`.
